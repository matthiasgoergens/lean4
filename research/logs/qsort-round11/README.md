# Sorting, round eleven, under extreme load (2026-10-27)

Round eleven of `sorts/PLAN.md` (production pdq with cutoff 24 against core on random keys), on the benchmark machine as six shards on CPUs 20–25, three blocks each (18 blocks).  The load rose to 156 as it started and stayed at 157–243 (median 211) on 128 hardware threads: the gate case took 8.8 s instead of about 1 s and even `none` used several times its usual CPU time.  The result measures a heavily oversubscribed machine, not the quiet case the round was planned for; it is kept as such, and the round is rerun when the load is low.  Every run picked one of 8 shuffled builds of commit 9a55c74's sources (`shuffled-binaries.sha256`).  `analysis.txt` is `sorts/analyse.py <dir> core`; `analysis-cpu.txt` is `sorts/analyse_cpu.py <dir> core`.
