  # Claim 1 — worker/wrapper value semantics

  No concrete correctness defect found for the supported cases. What I verified by inspection:

  - Eligibility is narrow and fail-closed: `recursive` flag, `.code` body, exactly one `Prod a b` param with both fields in the five native scalar consts, and a direct self-call passing the pair as an fvar (`SplitProd.lean:83-88`, `46-57`). Everything else is returned unchanged.
  - `redirect` (`SplitProd.lean:59-80`) is exhaustive over ANF call positions (all const calls are let-bound; it recurses through `fun`/`jp` bodies and case arms), splices args correctly including over-applications (`args.size >= arity` preserved on both sides), and leaves partial self-references calling the original name — i.e., the wrapper — which is sound and matches the documented limitation.
  - The worker reconstructs the pair as a let reusing the state's fvarId after `eraseParam` (`SplitProd.lean:99-105`), so escaping/aliased uses of the pair (e.g. `escapingPair`'s `seen.push s`, the base-case `return s`) observe the same value; the wrapper keeps the original name, type and ABI, preserves explicit `noinline`, and only marks the wrapper `inline` otherwise (`SplitProd.lean:120-124`), so partial applications retain the wrapper as claimed.
  - `Sink.place` (`SplitProd.lean:146-163`) is exhaustive over use locations: LCNF `.cases` nodes have no continuation, so discr + exactly-one-using-arm covers all uses; it stops at any let/fun/jp whose decl uses the pair (captures included via `collectUsed`) and never recurses into `fun`/`jp` bodies, so it cannot duplicate construction into a loop or break a capture. Sinking is confined to workers recorded in the branch-local `generatedWorkers` set (`SplitProd.lean:190`), and eligibility (`fields? decl.type`, scalar-only) means no reference-counted field's lifetime can be delayed — the lifetime claim holds by construction, not just by test.
  - The differential controls are genuinely differential: full stdout including the IO.Ref effect trace and the escaping-pair array is compared baseline-vs-split over 9 n × 4 seeds (`measure.py:206-214`), and the in-binary `check` calls compare against independent `Nat`-range references (`Semantics.lean:224-230`). I verified the reference recurrences match the recursive ones (including the UInt16 truncation in `pair32`/`reference32` and the byte checksum/`makeBuf` oracle agreement).

  Residual risk is the documented kind: this is bounded differential evidence plus the IR checker, not a proof; mono-phase dependent types, unusual self-reference shapes and mutual recursion are outside the supported envelope and are listed as such. I did not infer correctness from the passing tests; the above is a structural argument.

  # Claim 2 — the checked annotation

  No concrete fail-open path found. The checker's logic does what ANNOTATIONS.md claims:

  - Fail-closed ordering: option disabled → error before any state is read (`MustSplitProd.lean:25-26`); no group → error (`29-31`); missing mono body → error (`39-43`); every reachable `recursive` decl must be in `completedWorkers` and have no eligible pair param (`45-50`); at least one such worker required (`54-55`). Traversal follows all let-bound consts (any arity, including inside closures) filtered by the recorded group (`52-53`), and it traverses from the worker bodies too, so a split worker cannot mask a second unsplit worker reached only through it — `one_missed_loop` targets exactly this.
  - Masking via foreign evidence is blocked structurally: `completedWorkers` is only fed from `generatedWorkers`, which is only fed by the pass after a name-collision check (`SplitProd.lean:90-92`, `110`, `192`); the group filter confines the traversal to the recorded compilation group, so a pre-existing user `work._splitProd` (`fake_suffix`) or a separately compiled helper (`unrelated_success`) cannot manufacture evidence — both fail with `count == 0`, not a pass.
  - Async/replay/stale-evidence inspection (explicitly requested): `generatedWorkers` is `.local` (branch-scoped; the BUILD_FAILURES.md panic fix), the two evidence extensions are `.sync` with replay functions that merge only branch-new entries — idempotent for the name set, and last-write-wins for the group map is harmless because decl names are unique per module. The extensions are non-persistent, so no olean/cross-module leakage; the defining-module check (`MustSplitProd.lean:65-66`) plus group scoping blocks stale foreign evidence. If async ordering ever hid the `.sync` entries from the `afterCompilation` handler, the outcome is a false error ("no completed compilation group"), not a false pass — failure direction is closed. The checker only reads state (`24-55`); no second compilation, consistent with the abandoned approaches documented in ANNOTATIONS.md:48. The newer `module` format rejection is delegated to Lean itself and tested (`module_deferred`), and the prefix-`partial def` limitation is tested (`prefix_partial`).

  Minor note (P3, documentation): a user-defined `foo._splitProd` makes compilation of an eligible recursive `foo` fail with a hard "worker name collision" error (`SplitProd.lean:90-92`). The docs mention the suffix only in the evidence-manufacturing context (ANNOTATIONS.md:32); the collision-error behavior is only in a code comment. Worth one sentence in ANNOTATIONS.md.

  # Claim 3 — comparison harness and build admission

  The harness implements the described protocol: per-block independent shuffles of complete treatment sets from a seeded RNG (`measure.py:41-51`), fresh warmed processes with raw rows written and flushed before any failure is raised (`measure.py:54-74`, tested), checksum oracle in independent Python, abort-on-failure with no exclusions, the losing initial campaign retained in text, and build admission that invalidates before touching outputs, publishes atomically, binds sources/binaries/traces/commands, and preserves per-attempt logs (`build_state.py:7-30`, `build.py:39-40`, tested by `test_build_state.py`). Timing-claim framing (fixed binaries, one host, no layout distribution, descriptive intervals) is consistently hedged in README/DESIGN/issue.

  Findings here (all P3):

  1. **Coverage checks use substring matching, and required names alias.** `measure.py:140`/`144` and `verify.py:359`/`362` use `any(name in actual ...)` on trace lines. `LoopStudy.tailPair` is a substring of `LoopStudy.tailPairReturn` (the variant list at `measure.py:19-20` implies both names exist; Variants.lean is outside the bundle so I cannot confirm the exact Lean names). Scenario: a build that transforms `tailPairReturn` but silently stops transforming `tailPair` still passes the "expected transformation" requirement — the exact failure class this guard and `must_split_prod` exist to catch. Impact is limited because the timing table would show a ~1.0 ratio and verify.py recomputes checksums, so it weakens a provenance assertion rather than producing a false performance claim. Confidence: high that the code pattern aliases; medium on the actual names. Fix: compare the stripped traced name for equality (the trace emits exactly `decl.name`, `SplitProd.lean:127`).
  2. **The scalar timing kernels are not reviewable from this bundle.** `build.py:43` reads `../loop-study/Variants.lean`; all scalar-campaign variant shapes, the n/2 warmup convention assumed by `expected_checksums` (`measure.py:91-94`), and the `LoopStudy.*` names rest on that file. It is snapshotted into each campaign archive (`measure.py:196`), so published archives bind it — but this review package does not. Scope limitation, not a defect.
  3. **Coverage requirement lists are incomplete in two places.** The semantics-kind requirements (`measure.py:129-133`, `verify.py:24-30`) omit `CompilerStudy.tailPair`/`returnPair`/`sharedPair` — the canonical pair recursions — so a silent non-transformation of those in the semantics binary trips no coverage error (values are still protected by the stdout differential). Similarly scalar negative controls omit `for-nat` and `tail-fuel`. Conservative direction, but it is an assertion gap.
  4. **Summary recomputation is gated on a clean error list** (`verify.py:434` `elif not errors:`). Any earlier inconsistency exempts `summary.json` from recomputation. The archive still fails overall, so this only loses diagnostic specificity.
  5. **Plugin oleans are not hash-bound.** Admission binds sources, binaries, traces and commands (`build.py:58-66`) but not `SplitProd.olean`/`MustSplitProd.olean`, which `test_contract.py:107` links against. A stale/tampered olean would affect future contract-test runs without tripping admission; the measured binaries themselves are bound, so impact is low.
