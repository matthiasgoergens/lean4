The initial worker-splitting pass regresses `tail-pair-return`: at five million iterations its paired enabled/baseline ratio is 1.240 (descriptive interval 1.232–1.250), and the fresh half-size campaign reproduces it at 1.257 (1.241–1.274). The original while and scalar-result pair workers improve substantially. No observations were excluded.

The emitted C explains the specific missed optimisation. In the initial `split.c`, `tailPairReturn._splitProd` constructs the input pair before testing the bound, then destroys it on the continuing branch. It therefore allocates two scalar boxes and a new product every iteration. The ordinary while worker constructs its result only on exit. This is evidence against treating argument splitting alone as a sufficient optimisation.

The stock `FloatLetIn.initialDecisions` conservatively refuses some movements when constructor inputs are also used as potentially owned arguments later in the block. Its argument visitor does not distinguish these native scalar fields from objects. The retained input pair is needed only in the exit branch, but the stock pass leaves it above the branch. This source path motivates the next experiment; it does not establish a general defect in its ownership heuristic.
