Question: does the opt-in scalar-pair worker pass remove the diagnosed cost from unchanged Lean source, and does the effect transfer to a checked byte scan? The estimand is the median within-block ratio of pass-enabled time to baseline time for each source variant. A 10% time difference is practically meaningful. This is an exploratory compiler experiment; the previous study and generated code motivated it. This design precedes inspection of new performance observations.

Baseline and enabled executables are compiled from identical source with the same imported plugin, Lean 4.33.1, bundled Clang and `-O3 -DNDEBUG`. Only `compiler.splitProd` differs. The plugin is disabled by default. Both compilations enable `compiler.check`; the pass itself always requests an IR check. Preserve explicit `noinline` attributes. Compilation, traces, source hashes and executable hashes are retained. Build command durations and binary sizes are diagnostic observations, not a controlled compile-time effect estimate.

Each experimental unit is a fresh process: input construction/parsing, one half-sized warm-up, then a monotonic timed kernel invocation and checked output. Scalar campaigns use all ten variants from the earlier loop study, in both modes: twenty treatments per complete block. Every block gets a fresh independent shuffle from a recorded seeded RNG. No Latin square, forced alternation or position balancing. The sequence is prefix-stable, and any positive number of complete blocks is supported.

Before timing: run all scalar variants in both modes at bounds 0,1,2,17,1000 and seeds 0,1,2611923443488327891,UInt64.max; verify full and warm-up checksums against a Python oracle. Differential semantic tests compare full output and IO traces with the pass disabled/enabled, including small bounds and boundary seeds. Check which functions actually transformed so skipped cases are not misreported as positive coverage.

Primary scalar campaign: n=5,000,000, 30 blocks, RNG seed 20260916. Fresh-process size sensitivity: n=2,500,000, 20 blocks, seed 20260917. Both use value seed 2611923443488327891. Positive controls are the original Id/IO while and pair-recursive variants. Negative controls are scalar tail recursion, range for loops and concrete-state loops, which should not receive this transformation.

Byte transfer campaign: four variants in both modes, 20 complete blocks, size=1,048,576 bytes, rounds=16, value seed 2611923443488327891, RNG seed 20260918. The buffer is generated outside timing with byte `(i*31+7)%256`. The checksum recurrence and round separator match the earlier byte diagnostic. The original Nat-index while is a negative control for the pass's native-scalar-only guard; the USize-index while tests the eligible carrier while keeping checked indexing. Range for and concrete-state versions are source controls. This remains a diagnostic, not a real-application speedup. Small byte control grids and campaign-sized Python oracle checks precede timing.

Pin children to the highest initially allowed logical CPU, record topology, scheduler, nice/ionice, frequency policy and host load before/after each block. Use the inherited runtime/allocator defaults, record relevant non-secret Lean runtime environment switches, and do not reserve the CPU or change host frequency policy. Do not build or run other agent tests during timed campaigns. Nuisance factors include contention, thermal/frequency drift, code layout and caches. Blocking and shuffling mitigate them; they do not eliminate them.

Retain each raw invocation before validation, plus parsed observations and process wall time. Abort on failures or checksum mismatch; do not omit outliers. Finish the declared number of complete blocks, not a favourable result. Optional later extensions must record their rationale and retain all prior observations; the current planned campaigns have fixed counts.

Report per-mode median milliseconds and median paired ratios with descriptive percentile bootstrap intervals from 20,000 block resamples. Report all variants, including unaffected and losing ones. Do not make multiplicity-adjusted significance, equivalence or cross-application claims. Keep the half-size campaign separate. Internal IR validation and differential tests are evidence for this prototype, not a proof of compiler correctness.
